## 1. サービス概要

**サギカモ**: 不審な電話の内容・メール・SNSの文面を貼るだけで、
(1) 生成AIが手口の型を見立て、(2) 警視庁オープンデータから「その手口が、いまユーザーの街で何件起きているか」を提示し、
(3) 次にとるべき行動（切る/無視/#9110/188/110）まで案内する詐欺被害防止サービス。

- 差別化の核は「LLM判定」ではなく「**判定×東京都の実データ照合**」。判定結果には必ず地域の実件数と出典を添える。
- 断定しない。「詐欺です/ではありません」は出力しない（CLAUDE.mdルール1）。
- スマホWebファースト（PWA）。登録・ログイン不要。起動画面＝貼り付け画面。

### ペルソナ（実装判断用の要約）
- A: 35歳会社員。実家に70歳の独居の母。自分にも投資DM・フィッシングSMSが届く。→ 判定と「まもるカード」共有の主体
- B: 70歳独居。スマホはLINEのみ。→ 大きな文字・やさしい文・「見るだけ」で伝わるカードの受け手

## 2. データ仕様（東京都オープンデータ）

### 2.1 APIの前提
- 東京都オープンデータカタログのCSV約35,000件はすべてJSON/XMLのAPIで提供。**登録・キー不要**。
- apiIdは APIカタログサイト（https://spec.api.metro.tokyo.lg.jp/）で対象データを検索して特定する。
  リクエストは limit（件数）・column（項目絞り込み）等のパラメータを指定可能。使い方: https://spec.api.metro.tokyo.lg.jp/spec/usage
- 統計データは**月次バッチで取得→整形→キャッシュ**（`data/cache/`またはKV）。画面リクエスト時にAPIを直叩きしない。
- 全画面表示に「出典: 〔データ名〕（〔提供元〕、〔取得年月〕）」を付ける。

### 2.2 使用データ一覧

| ID | データ | 提供元 | 用途 | 取得 |
|----|--------|--------|------|------|
| D1 | 区市町村の町丁別、罪種別及び手口別認知件数（月累計） | 警視庁 | 【中核】詐欺関連手口の地域件数。F-01の判定結果への併記、F-02マップの母数 | オープンデータAPI（apiIdはPhase Aで特定） |
| D2 | 犯罪発生情報（年計） | 警視庁 | F-02の経年トレンド（前年比） | カタログCSV/API |
| D3 | 住民基本台帳による世帯と人口（年齢別） | 東京都総務局 | F-02リスク指数の分母（高齢者人口） | カタログCSV/API |
| D4 | 高齢者等の異変等に気付いた際の区市町村連絡先 | 東京都福祉局 | F-05の区市町村別連絡先 | カタログCSV/API |
| D5 | 特殊詐欺の手口・統計（警察庁・警視庁公表資料） | 警察庁/警視庁 | F-03図鑑とF-01プロンプトの分類定義の出典（データではなく知識ベース） | 公表資料から人間が整理→`data/config/techniques.json` |

- D1の注意: 手口分類の値一覧（「詐欺」系の内訳）はPhase Aで実データから確認し、`docs/data.md`に記録する。
  「詐欺関連手口」の抽出条件はコードにハードコードせず設定ファイル化する。
- D1は月累計。最新月（令和8年6月累計→8月上旬掲載）をハッカソン直前に再取得する。

### 2.3 独自指標（F-02）
- **リスク指数 = 当年の詐欺関連手口認知件数 ÷ 65歳以上人口 × 10,000**（高齢者1万人あたり件数）
- 区市町村単位（62自治体）で算出。町丁別はPhase 1で検討。0除算・人口データ欠損時は「算出不可」を表示（0にしない）。

## 3. 機能要件

### F-01 サギカモ判定【Must】
入力: テキスト貼り付け（メール・SMS・DM・電話内容の要約）。画像OCRは時間があれば（Should）。

出力（4点セット、JSONスキーマで構造化）:
1. `risk`: "high" | "caution" | "low"（表示名: 要注意/注意/低リスク）
2. `technique`: `techniques.json`のIDに紐づく手口の型（該当なしは "unknown"）
3. `evidence[]`: 根拠となる特徴（例:「公的機関を名乗る」「電話でATM操作を指示」「LINEへの誘導」）最大5件
4. `action`: 推奨行動（切る/無視・ブロック/#9110/188/110 の組み合わせ）

表示要件:
- 判定結果に **D1由来の地域件数を必ず併記**（例:「還付金詐欺の型に近い特徴です。◯◯区では今年◯件認知されています（出典: 警視庁…）」）。
  地域未選択時は都全体の件数を表示。
- `risk=low` でも定型注意文を必ず表示（CLAUDE.mdルール1）。
- 応答目標: 貼り付け→表示まで10秒以内。

実装要件:
- LLMは構造化出力（JSONスキーマ強制）。自由文の生成はテンプレートへの流し込みで行い、断定表現が混入しない構造にする。
- プロンプトの知識ベースは `techniques.json` のみ。件数・地名をLLMに出力させない（データ層で結合する）。

受け入れ基準:
- [ ] テストセット20件（`data/testcases/testcases.csv`）で**危険側の見逃し（明白な詐欺文面をlow判定）ゼロ**
- [ ] 全出力に断定表現なし（`scripts/eval.ts`で文字列チェックを自動化）
- [ ] 地域件数と出典が表示される

### F-02 地域リスクマップ【Must】
- 62区市町村を地図（MapLibre）に色分け。指標は 2.3 のリスク指数。手口別フィルタ、当年/前年切替。
- 2地点比較: 「自宅」「実家」の2区市町村を保存（localStorage相当のクライアント保存でよい。サーバー保存しない）し切替表示。
- F-01結果画面から「あなたの街を見る」で遷移。

受け入れ基準:
- [ ] 62区市町村すべてに指数または「算出不可」が表示され、出典明記
- [ ] 2地点の切替が動作

### F-03 手口図鑑【Must】
- `techniques.json` の手口カード一覧。各カード:〔型の名前／典型フレーズ2-3例／狙われやすい状況／初動〕＋都内当年件数（D1）。
- 分類は警察庁の令和8年再整理（ニセ警察詐欺・SNS型投資・ロマンス詐欺を含む）に準拠。フレーズは公表資料の範囲（創作しない）。

### F-05 相談導線【Must】
- 危険度別の出し分け: 被害発生・切迫→110／不審だが被害なし→#9110／契約・消費トラブル→188。使い分けの1行説明付き。
- D4データで区市町村別の「高齢者等の異変時連絡先」を選択表示。
- 全画面フッターに常設。

### F-04 まもるカード【Should / Phase 1】
- 判定結果・手口カードから家族向け共有画像を生成（Canvas/OG画像）。やさしい日本語・大きな文字。
- MVPではボタンとモック画像まででよい（動線の存在をデモで見せる）。

### F-06 予兆アラート【Could / Phase 2】— MVPでは実装しない。

## 4. 画面仕様

| No | 画面 | 内容 |
|----|------|------|
| S-01 | ホーム（貼り付け） | テキストエリア＋「判定する」ボタンのみ。説明・登録・チュートリアルなし。フッター: 相談導線＋下部ナビ |
| S-02 | 判定結果 | 上から: 危険度（色+アイコン+文言の冗長表示）→手口の型→根拠リスト→**地域件数（出典付き）**→推奨行動ボタン→「あなたの街を見る」→まもるカード（Phase1） |
| S-03 | 手口図鑑 | カードグリッド→詳細 |
| S-04 | リスクマップ | 地図＋手口フィルタ＋2地点切替＋凡例・出典 |
| S-05 | 相談窓口 | 110/#9110/188の使い分け＋区市町村セレクタ→D4連絡先 |

### デザイン原則（実装判断に使う3か条）
1. **断定せず、根拠で語る**: LLMの見立て（グレー系）と実データ（アクセント色）を視覚的に区別する。
2. **怖がらせて終わらせない**: 危険度の直下に必ず行動ボタン。赤一色の警報UIにしない。
3. **貼るまで0秒**: 起動画面=貼り付け画面。判定まで3タップ以内。

### トンマナ
- キーカラー: ネイビー `#1F3A5F`（信頼）／注意: アンバー `#E6A23C`（1段階のみ、赤不使用）／安全行動: グリーン `#7BB661`
- 文字: 最小16px、コントラスト比4.5:1以上、色+アイコン+文言の冗長表示（色覚多様性対応）
- ボイス: 「隣にいる冷静な家族」。例: ×「危険！今すぐ確認！」→ ○「あわてなくて大丈夫。まず電話を切って、この番号で確認しましょう」

### マイクロコピー（確定文言。変更時は人間に確認）
- 初回: 「怪しいと思ったら、撮って送るだけ。判定の根拠は、東京都の実データです」（2026-08-16 人間の承認により「ここに貼るだけ」から変更）
- low時の定型注意文: 「今回の内容に、知られた手口の強い特徴は見つかりませんでした。ただし新しい手口の可能性は残ります。お金の話が出たら、一度切って相談を」

## 5. 非機能要件

- 判定応答10秒以内／マップ描画5秒以内。統計はキャッシュから返却。
- 貼り付け内容の非保存（CLAUDE.mdルール2）。統計イベントのみ収集: `judge_run`（分類・危険度・区市町村のみ）, `consult_tap`, `card_share`, `zukan_view`, `map_switch`。
- オフラインデモモード: `data/seed/` のスナップショットで全画面が動くこと（審査当日のAPI/LLM障害対策）。使用中は「サンプルデータ」表示。
- 入力テキスト内URLへのアクセス禁止（CLAUDE.mdルール5）。

## 6. 技術構成

```
sagikanchi/
├── CLAUDE.md
├── docs/            # spec.md / tasks.md / data.md(Phase Aで生成)
├── data/
│   ├── config/techniques.json   # 手口分類定義（人間が出典から整備）
│   ├── testcases/testcases.csv  # 評価用20件（人間が管理・Claudeは改変禁止）
│   ├── cache/       # APIから取得・整形した統計JSON（月次更新）
│   └── seed/        # デモ用スナップショット
├── scripts/         # fetch_opendata.ts / build_stats.ts / eval.ts
├── src/
│   ├── lib/llm/     # 判定クライアント抽象化（プロバイダ差し替え可能）
│   ├── lib/stats/   # 統計結合・リスク指数
│   └── ui/          # React (Vite) + MapLibre
└── workers/         # Cloudflare Workers（判定プロキシ・統計収集）
```

- 判定LLM: 開発時はAnthropic API等、本番はOpenCode提供LLM。`src/lib/llm/client.ts` のインターフェースで切替。
- デプロイ: Cloudflare Pages（UI）+ Workers（API）。ローカルは `wrangler dev`。
