## 0. API共通仕様

- エンドポイント: `POST https://service.api.metro.tokyo.lg.jp/api/{apiId}/{json|xml}`
  - apiId 形式: `{データセットID}-{リソースハッシュ}-{シート番号}`（例: `t000022d1700000021-0632e...-0`）
  - ヘッダ: `accept: application/json` / `Content-Type: application/json`、ボディは `{}` でよい
  - パラメータ: `limit`（件数）、`column`（項目絞り込み）、`searchCondition`（検索条件）
  - 使い方: https://spec.api.metro.tokyo.lg.jp/spec/usage
- APIレスポンスは UTF-8 の JSON。`{total, subtotal, limit, offset, metadata, hits[]}` 構造。
  `metadata.dataTitle` に表名が入るため、apiId の同定検証に使える。
- apiId の探し方: APIカタログの検索ページ `https://spec.api.metro.tokyo.lg.jp/spec/search?q=キーワード`
  （データセットIDでの検索は不可。タイトル語句で検索する）。
- CKANカタログAPI（データセット特定に有用）:
  `https://catalog.data.metro.tokyo.lg.jp/api/3/action/package_search?q=...` / `package_show?id=...`

### 1.4 ⚠️ 詐欺関連手口の抽出条件（最重要の発見）

**D1に特殊詐欺の内訳（ニセ警察・還付金・オレオレ等の手口別件数）は存在しない。**
詐欺関連の列は以下のみ:

- `その他詐欺` … 刑法犯「詐欺」の認知件数（特殊詐欺もここに包含されるが内訳なし）
- （参考）`その他その他知能犯` … 詐欺以外の知能犯

**抽出条件案: 「詐欺関連手口 = `その他詐欺` 列」の1本とする。**

製品仕様への影響（ゲートで要判断）:
- F-01の地域件数併記: 「◯◯区では今年、詐欺（刑法犯）が◯件」という**詐欺全体の件数**は出せる。
  「還付金詐欺が◯件」のような**手口別の地域件数は出せない**。
- F-02マップの「手口別フィルタ」: D1では実現不可。「詐欺全体」の1指標に変更するか、代替データが必要。
- F-03図鑑の「都内当年件数（手口別）」: D1では不可。警視庁が別途公表する特殊詐欺手口別統計
  （都全体の値。区市町村別ではない）を人間が確認して代替する等の判断が必要。

### 1.5 行構造（集計時の必須知識）

ファイルは2セクション構成（R8.csv 実測。R7 APIも同一構造）:

1. **町丁別セクション**（先頭〜約4,944行目）: 「千代田区飯田橋１丁目」等の町丁行。
   各自治体ブロック末尾に「**◯◯計**」小計行（例: 大島町計、小笠原村計）が混在。
2. **区市町村サマリーセクション**(末尾68行): 自治体名そのものの行（「千代田区」等）が62行
   → 「２３区計」「多摩地区・島部計」「他県」「海外認知」「不明」「合計」。

- **区市町村単位の値はサマリーセクションの完全一致行から取ること。**
  前方一致で町丁行を積み上げると「◯◯計」小計行と二重計上になる（実測で確認済み: 単純積上げは正値の2倍になった）。
- 検算結果（R8・その他詐欺列）: 23区積上げ 4,855 = ２３区計 ✔ ／ 多摩・島部積上げ 1,652 = 多摩地区・島部計 ✔ ／
  4,855 + 1,652 + 他県49 + 海外認知5 + 不明50 = 合計 6,611 ✔
- 62区市町村すべてにサマリー行が存在することを確認済み。
- 注意: 「西多摩郡檜原村」は町丁別セクション（町丁内訳なしの単独行）とサマリーセクションの両方に同名で出現する。
  行位置（サマリーセクション内か）で判別すること。
- 島しょ部の自治体名は「三宅島三宅村」「八丈島八丈町」表記（D3と異なる。§2.3参照）。
