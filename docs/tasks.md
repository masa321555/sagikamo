# サギカモ フェーズ別タスクリスト

原則: **フェーズ順に進め、先回りしない**。各フェーズ末尾の完了条件を自己チェックし、
結果を報告して人間の確認（ゲート）を待ってから次へ進む。
失敗時はダミーで代替せず停止・報告（CLAUDE.mdルール4）。

## Phase A: データ検証（最優先・実装コードは書かない）

**目的: 中核データD1が本当に取れるかで本案の生死が決まる。UIより先。**

- [ ] A-1: APIカタログ（https://spec.api.metro.tokyo.lg.jp/）で警視庁
      「区市町村の町丁別、罪種別及び手口別認知件数（月累計）」を検索し、apiIdを特定する
- [ ] A-2: 実際にAPIをfetchし、レスポンス（JSON）のスキーマ・件数・文字コードを確認する
- [ ] A-3: 「手口」列の値一覧を全件抽出し、詐欺関連手口（特殊詐欺の内訳等）の候補を列挙する
- [ ] A-4: D3（年齢別人口）・D4（区市町村連絡先）についても同様にapiId特定とサンプル取得
- [ ] A-5: 調査結果を `docs/data.md` に記録
      （各データ: apiId / リクエスト例 / スキーマ / 値一覧 / 詐欺関連手口の抽出条件案 / 注意点）

**完了条件**: docs/data.md が存在し、D1の実レスポンス断片（先頭数件）と手口値一覧が貼られている。
**ゲート**: 人間が data.md を確認し、「詐欺関連手口の抽出条件」を承認してから Phase B へ。
**A失敗時（D1が取得不可）**: 停止して報告。→ 人間が代替（防犯ネットワークデータ等）を判断する。

## Phase B: データパイプライン

- [ ] B-1: `scripts/fetch_opendata.ts` — D1/D3/D4を取得して `data/cache/raw/` に保存（取得日を記録）
- [ ] B-2: `scripts/build_stats.ts` — 区市町村×手口×月の集計、リスク指数（spec 2.3）算出、
      UI用JSON（`data/cache/stats.json`）を生成
- [ ] B-3: 検証: 集計値の独立検算（別ロジックでの再計算と突合）、62区市町村の網羅チェック、
      欠損・0除算の扱い確認。結果をコンソールにPASS/FAIL形式で出力
- [ ] B-4: `data/seed/` にデモ用スナップショットを固定コピー

**完了条件**: stats.json が生成され、検算スクリプトが全PASS。任意の区の指数を人間がスポットチェックできる状態。
**ゲート**: 人間が2〜3区市町村の件数を警視庁公表ページと目視突合してから Phase C へ。

## Phase C: 判定エンジン＋評価ハーネス

- [ ] C-1: `src/lib/llm/client.ts` — LLMクライアント抽象化（開発用/本番用の差し替え口）

      断定表現が構造的に入らない表示テンプレート

- [ ] C-4: `scripts/eval.ts` — testcases.csv を判定に通し、期待値と突合。
      出力: 全体正答率／**危険側見逃し一覧（最重要）**／断定表現の混入チェック（自動grep）

**完了条件**: eval.ts で「危険側見逃しゼロ」「断定表現ゼロ」を達成。
**ゲート**: 人間がeval結果と判定サンプル5件の文面トーンを確認してから Phase D へ。
※ここが達成できない場合が仕様書のGo/No-Go判断点。人間に報告して指示を待つ。
